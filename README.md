# Auto-response：微信提需求，家里的 Claude Code 自动开发

朋友在微信（企业微信）里用大白话提需求 → 阿里云百炼（通义千问）理解需求、识别是哪个项目 → 家里电脑上的 Claude Code 自动改代码、跑测试、合并 → 结果发回微信。
**小改动全自动，部署上线前需要你在手机上回复「同意」。**

```
 朋友（个人微信 / 企业微信）            你（企业微信，审批 + 通知）
        │  提需求、发截图                    ▲  「同意 12」
        ▼                                   │
 ┌──────────────────────── 阿里云 ECS ────────────────────────┐
 │  企业微信回调 → 消息合并 → 百炼理解需求 → 任务队列 → 回复/审批  │
 └────────────────────────────────────────────────────────────┘
        ▲  HTTPS 长轮询（家里电脑主动连出，不需要公网 IP / 端口映射）
        │
 ┌──────────────── 家里 Windows 电脑 ────────────────┐
 │  Agent → 新建分支 → claude -p 改代码 → 测试 → 合并   │
 │        → 打包安装包（自动）/ 部署（你确认后）          │
 └──────────────────────────────────────────────────┘
```

## 一个需求的完整流程

1. 朋友：「商城后台登录页的按钮改成蓝色」「字也加粗一点」（可以连发多条、发截图）
2. 服务器等 15 秒把连续消息合并，交给通义千问判断：是新需求/补充/问进度/闲聊，属于哪个项目，改动大小
3. 回复朋友：「收到！任务 #12【登录按钮改蓝加粗】已加入队列…」
   - 改动较大（数据库变更、删功能、支付权限等）→ 先发给你确认
4. 家里电脑拿到任务：在项目里新建分支 `claude/task-12` → 调用 Claude Code（订阅账号）实现 → 自动提交 → 运行配置的测试命令
5. 测试通过 → 合并到主分支 → 朋友收到 Claude 写的通俗说明；需要出安装包的项目会自动打包并发下载链接
6. 有部署命令的项目 → 你收到「回复 同意 12 部署上线」→ 回复后家里电脑执行部署 → 朋友收到「已上线」

失败、超时、测试不通过时，代码保留在分支上，你会收到错误详情，朋友只会收到「已通知负责人处理」。

## 微信里的指令

| 谁 | 指令 | 作用 |
|---|---|---|
| 所有人 | 直接描述需求 | 新需求 / 对上一个需求的补充 |
| 所有人 | `进度` / `进度 12` | 查看任务列表 / 详情 |
| 所有人 | `取消 12` | 取消排队中或正在执行的任务 |
| 所有人 | `帮助` | 用法说明 |
| 你 | `同意 12` / `拒绝 12` | 确认大改动 / 确认部署（或拒绝） |
| 你 | `部署 项目id` | 手动部署某个项目 |
| 你 | `授权 kf:xxx 小李` | 允许新用户提需求（陌生人发消息时你会收到提示） |
| 你 | `用户` | 查看已授权用户 |

## 安全设计

- **只有授权用户能提需求**：陌生人的消息不会被处理，只会提醒你
- **Claude 权限受限**：只允许读写代码和运行常见的构建/测试命令；禁止 git 提交/推送/切换分支、删除目录、发布等操作
- **每个需求一个分支**：测试不过不合并，随时可以回滚
- **部署必须你确认**；大改动开工前也要你确认
- **家里电脑不对外暴露端口**；Agent 与服务器之间用 HTTPS 加 Token 认证
- **密钥不进仓库**：`.env`、`config.yaml` 已被 gitignore（本仓库是公开的，千万别把密钥写进代码）

## 目录结构

```
server/            云端服务（FastAPI + SQLite）
  app/wecom/       企业微信加解密、API
  app/triage.py    百炼/通义千问需求理解
  app/dispatcher.py核心调度：合并消息、建任务、审批、通知
  app/main.py      HTTP 接口
agent/             家里 Windows 电脑上的 Agent
  bridge_agent/    长轮询、调用 Claude Code、git 分支管理、测试/打包/部署
  config.example.yaml
  install_windows.ps1  开机自启
deploy/            服务器部署：systemd、Nginx、.env 模板
docs/setup.md      详细部署步骤（企业微信 → 服务器 → 家里电脑）
```

## 开始部署

按 [docs/setup.md](docs/setup.md) 的三个步骤操作，大约 1 小时：

1. 企业微信：注册、建自建应用、（可选）开通微信客服让朋友直接用个人微信
2. 阿里云 ECS：部署 `server/`，配置域名证书
3. 家里电脑：安装 Agent，配置项目，设置开机自启

## 开发

```bash
pip install -r server/requirements.txt -r agent/requirements.txt pytest
python -m pytest
```

测试覆盖：企业微信加解密、消息合并与去重、授权、任务/审批/部署状态流转、百炼结果解析与兜底、Agent 的分支/提交/测试/合并/取消/暂存/打包，以及服务器与 Agent 的端到端流程（Claude 用假脚本代替）。
